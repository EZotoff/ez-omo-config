# Plugins

This directory packages OpenCode plugins copied from the local plugin registry for reuse in `ez-omo-config`.

## Included plugins

- `worktree.ts` — creates isolated git worktrees for AI sessions and coordinates session state plus terminal spawning. The `worktree_start` tool resolves plans from both `.omo/plans/` (canonical, read by OMO's `/start-work`) and `.sisyphus/plans/` (legacy `/prometheus-plan` default); when a plan is found only at the legacy location, it is auto-copied to `.omo/plans/` before `/start-work` is dispatched, so the pipeline works regardless of which location the planner wrote to. The `worktree_delete` tool accepts an optional `target` (branch name or absolute path), so the main session can reclaim any allocated worktree — not just its own — through the proper hook path: pre-delete hooks run, uncommitted changes are snapshotted to the branch, and the branch is deleted only when fully merged (lowercase `-d` semantics; the main repo worktree is refused).
- `worktree/state.ts` — SQLite-backed persistence for worktree session state and pending operations used by `worktree.ts`.
- `worktree/terminal.ts` — cross-platform terminal spawning and tmux helpers used by `worktree.ts`.
- `git-safety.ts` — blocks destructive shell and git commands and reports working tree safety before risky operations. Three layers: (1) always-block non-git destructive ops (`rm -rf` non-safe targets, `chmod -R 777`, `dd of=/dev/`, etc.); (1.5) **history-rewrite block** — `git commit --amend`, `git rebase`, `git push --force*`, `git branch -D`, `git stash clear`, `git reflog expire`, `git gc --prune`, and `git reset <ref>` where `<ref>` is a strict ancestor of HEAD (always blocked, regardless of dirty state — catches the post-commit destructive case); (2) dirty-tree-conditional git destructive ops (`git reset --hard`, `git clean -f`, `git checkout -- .`, `git restore`, etc.). Status checks resolve the bash command's actual cwd (`workdir` arg → leading `cd <path>` → `ctx.directory`) so worktree work is covered. Commit/tag message payloads (`-m "..."`, `--message="..."`) are stripped before pattern matching to avoid false positives when a commit message mentions a destructive command.
- `review-enforcer.ts` — injects review workflow instructions after task completion so plan execution gets reviewed consistently. Injection is gated: consultative subagent or category dispatches (oracle/metis/momus/explore/librarian/multimodal-looker/document-writer, category mephistopheles) are skipped — analysis work has no implementation to review — as are OMO sync-task abort stubs (`Aborted\n\nto continue: task(task_id=...`), degenerate outputs (<250 chars, no success indicator), and dispatches carrying the `[REVIEW-TASK]`/`[REVIEW-FIX]`/`[DEBATE]` marker. The plan-complete instruction fires only for sessions inside the active boulder's `session_ids` lineage (mirrors OMO's `resolveActiveBoulderSession` predicate, `opencode:` prefix normalized) when the boulder status is not paused/abandoned. Guards against stale machine-global `boulder.json` hijacking unrelated sessions and review mandates stamped on provider-exhausted corpses (2026-08-16 and 2026-08-19 debate-session misfires; regression pairs 014/015/016). The `/debate` skill prefixes all its task() dispatch prompts with `[DEBATE]` so judge categories (artistry/writing/ultrabrain — which also do implementation work elsewhere) skip injection. **Export contract**: the plugin entry exports ONLY the plugin function + default — OpenCode's loader (`getLegacyPlugins`) calls every function export as a plugin constructor, so pure helpers live in `review-enforcer/helpers.ts` (2026-09-08 `output.includes is not a function` incident; regression pair 018).
- `auto-checkpoint.ts` — semantic session-scoped git checkpointing. Enabled on this machine via `OPENCODE_AUTO_CHECKPOINT_ENABLE=1` set in **both** `~/.config/openchamber/openchamber.env` (port 3021 server) AND `~/AI_projects/omo-tg/.env` (port 4096 server, spawned by `omo-tg.service`). Timings: 30s idle threshold, 5min cooldown. On a fresh install without the env vars, plugin loads but returns empty hooks.
- `agent-git-workflow.ts` — force-loads (via `experimental.chat.system.transform`) a parallel-agent git coordination procedure into every session's system prompt: commit reflex, Conventional Commits format (no author override — attribution owned by git_master config), branching reflex when concurrent agent work is detected, sync/rebase protocol, and a worktree-aware branch lifecycle: merge `--no-ff` from the main worktree, then `git worktree remove` + lowercase `git branch -d` (`-D` is blocked by git-safety); prefer `worktree_delete` for worktree branches; dirty worktrees must be diffed and ported, never silently discarded. Fixes the allocation/reclamation asymmetry that leaked 14 worktrees+branches (May–Jul 2026). Complements auto-checkpoint (which handles idle-timeout safety-net commits) and the commit-policy patches (which grant permission).
- `session-id.ts` — copies the invoking session ID to clipboard via `/session-id`, confirms via TUI toast (`client.tui.showToast`, no console output), then sets `output.cancelled = true`. True no-LLM behavior depends on the active `opencode--command-hook-cancellation` patch.
- `session-info.ts` — copies project path, git branch, session title, and invoking session ID to clipboard via `/session-info`, confirms via TUI toast (`client.tui.showToast`, no console output), then sets `output.cancelled = true`. True no-LLM behavior depends on the active `opencode--command-hook-cancellation` patch.
- `clickable-links.ts` — injects a system-prompt instruction telling models to format file references as `[label](file:///abs/path)` markdown links so they are clickable in the TUI.
- `kdco-primitives/` — shared helpers used by the plugin bundle, including project ID lookup, shell escaping, tmux detection, temp paths, logging, timeout helpers, and shared types.

## Dependency notes

- `worktree.ts` depends on `./worktree/state` and `./worktree/terminal`, so those files must stay alongside it under `plugins/worktree/`.
- `worktree.ts`, `worktree/state.ts`, and `worktree/terminal.ts` all depend on `plugins/kdco-primitives/`.
- `kdco-primitives/` should be installed with the rest of the plugin bundle; moving or removing it breaks worktree-related imports.
- `review-enforcer.ts` depends on `./review-enforcer/helpers` — keep `plugins/review-enforcer/` installed beside the plugin entry (the loader auto-loads only top-level `~/.opencode/plugin/*.ts`, so the helpers submodule is safely off the plugin surface).

## Portability

- Files are copied as-is from the source plugin bundle.
- This repo intentionally avoids hardcoded personal paths or embedded secrets in the packaged plugin sources.
